# Built-in user roles in Bold Reports<sup>®</sup> UMS and sites

In Bold Reports<sup>®</sup>, users with admin permissions in both the User Management System (UMS) and reporting sites control user accounts, access, and site settings. These admin users oversee user accounts, access privileges, and site configurations. The following sections describe what admin users can do on UMS and on reporting sites.

## What can an admin do in UMS?

An admin in the Bold Reports<sup>®</sup> User Management System (UMS) has the following permissions:

* **Add, Edit, and Delete User Accounts**: Administrators can generate new user accounts, alter existing user details, and deactivate or remove user accounts when required.

* **Assign Permissions**: Admins can designate additional administrators for other users, distributing the responsibilities of managing user accounts.

* **Create and Manage Reporting Sites**: Administrators can establish and oversee multiple reporting sites, which function as segregated environments for distinct departments, clients, or projects.

* **Define Site Settings**: Administrators can configure site-specific settings, including branding, appearance, and access controls. The customization ensures the uniqueness of each reporting site.

## What can an admin do within a reporting site?

A site administrator in a Bold Reports<sup>®</sup> reporting site has the following permissions:

* **User Account Management**: Site administrators can add, modify, and remove user accounts within the reporting site they are assigned to.

* **Group Management**: Admins can create, edit, and delete user groups within their reporting site. Groups simplify the management of permissions.

* **Assign and Modify Group Permissions**: Admins can allocate precise permissions to user groups, thereby regulating access to reports and resources within their site.

* **Control User Access**: Administrators can grant or withdraw user access to the reporting site along with its contents.

* **Configure Site Settings**: Site admins can fine-tune site-specific settings, including design, layout, and data sources, to align with the requirements of their reporting environment.

* **Content Management**: Site administrators are responsible for overseeing the management of reports, data sources, and datasets within their reporting site, ensuring an organized and accessible collection of content.

## How do I enable admin permissions?

Bold Reports<sup>®</sup> knowledge base articles guide you through the steps to grant admin permissions to users within the User Management System and reporting sites. See the articles for [UMS](https://support.boldreports.com/kb/article/13501/how-can-enable-the-admin-role-for-newexisting-user-with-ums) and [Reporting Sites](https://support.boldreports.com/kb/article/13502/how-can-enable-the-admin-role-for-newexisting-users-with-reporting-site).

## Who can enable the admin role

In Bold Reports<sup>®</sup>, only users with existing administrative privileges can enable the admin role for others. Regular users without administrative access lack the authority to assign the admin role to anyone.

The restriction ensures that administrative privileges are granted solely to authorized individuals responsible for managing users and system settings within the Bold Reports<sup>®</sup> platform. Enabling the admin role is typically reserved for superusers, system administrators, or individuals with equivalent high-level access and responsibilities.

## Frequently asked questions

### Can a regular user assign the admin role?

No. In Bold Reports<sup>®</sup>, regular users without administrative access lack the authority to assign the admin role to anyone.

### What is a reporting site in Bold Reports<sup>®</sup>?

A Bold Reports<sup>®</sup> reporting site functions as a segregated environment for distinct departments, clients, or projects. UMS administrators can establish and oversee multiple reporting sites.
